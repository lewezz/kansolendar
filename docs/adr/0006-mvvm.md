# ADR-0006: Focused presentation, domain, and storage boundaries

Documentation updated: 2026-10-05.

## Context

The code must be understandable without introducing a framework layer for every operation.

## Decision reflected in the current source

Use a MainActor observable view model per root/window, validated domain values in KansolendarCore, and an actor-facing vault API in KansolendarStorage. Extract cohesive presentation adapters and shared persistence primitives.

## History and superseded assumptions

MVVM/domain/storage separation was the initial architecture. The implementation uses actual vault methods rather than the earlier proposed folder tree, generic ports, or extra service targets.

## Consequences

Date conversion, error text, and theme preferences have dedicated app owners. Business atomicity stays in storage; C handles and key bytes do not cross into views. See [code structure](../code-structure.md).

## Status

Implemented in source and refined by the maintainability pass. Current verification limits are tracked in [testing](../testing.md).
