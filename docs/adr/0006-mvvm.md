# ADR-0006 — MVVM con dominio y repositorios pequeños

## Context

Se requiere MVVM/Domain/Services/Repositories/Persistence, evitando una arquitectura de plataforma distribuida. Fechas/recurrencias deben probarse sin UI ni SQLite.

## Decision

Target App SwiftUI con ViewModels; paquete local de dos módulos Core/Storage. Core define reglas, casos de uso coordinados y puertos; Storage los implementa. App construye dependencias manualmente. Carpetas separan servicios/seguridad sin crear un target por clase. Repositorios expresan operaciones de negocio y transacciones atómicas.

## Alternatives

SQL en ViewModels mezcla privacidad y presentación. Un solo archivo/objeto global impide pruebas y control de sesión. Clean Architecture con muchos paquetes, DI framework, bus/CQRS y microservicios añade indirection y dependencias sin necesidad.

## Consequences

Hay algunas interfaces para límites reales, no protocolo por cada valor. Core no conoce SQLite/CryptoKit. La dependencia de código es distinta del flujo runtime. Módulos no protegen memoria frente a código malicioso del mismo proceso; sí hacen revisable quién maneja claves y persistencia.

## Status

Patrón general fijado por requisitos; granularidad propuesta. Ver [arquitectura](../architecture.md).
